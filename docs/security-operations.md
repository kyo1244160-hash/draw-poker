# セキュリティ修正の運用確認

## デプロイ

- Node.js は `.nvmrc` / `render.yaml` の指定に揃える。
- `migrations/add_three_card_settlements.sql` はポイント精算の重複防止テーブルを作成する。アプリも起動時に同じテーブルを作成するが、DDL 権限を分けている環境では事前にSQLを適用する。作成に失敗した場合は起動を中止する。
- `/api/health` の `revision` はRender上のコミット識別子、`runtimeSupported` は実行中のNode.jsが要求範囲を満たすかを示す。
- Socket.IO の負荷テスト認証を変更したため、テスト実行元と接続先のサーバーを同じ修正版に揃える。
- 通常運用では `LOAD_TEST_ENABLED=false` にする。
- 負荷テスト先は `NEXTAUTH_URL` とローカルサーバーに限定する。別の管理対象サーバーを使用する場合だけ `LOAD_TEST_ALLOWED_ORIGINS` に許可するオリジンをカンマ区切りで設定する。署名鍵は接続先と一致させ、第三者のサーバーを指定しない。

## ポイント精算

- スリーカードポーカーは同じアカウントの重複着席を禁止する。
- ベット後の退室・切断では精算用のプレイヤー情報を残し、未決定ならフォールドする。既に選択した PLAY は維持する。
- 精算はハンドIDとアカウントIDをキーにDBトランザクションで一度だけ反映する。
- DB反映に失敗した卓は次ハンドへ進めず再試行する。長時間止まる場合はDB接続・テーブル権限を確認する。
- 未精算ハンド自体の状態はメモリ内にある。プロセス強制終了からのハンド復元は今回の修正対象外。進行中の本番サーバーを強制再起動しない。

## ログと個人情報

- ランキング公開APIにはニックネーム・ポイント・参加回数だけを返す。
- 認証時のメールアドレス・Google ID、DB接続URL・クエリエラー詳細は出力しない。
- クライアントエラーログではIP・User-Agent・任意の追加情報を保存せず、URLの認証情報・クエリー・フラグメントなどを除去する。自由文の自動マスキングは完全ではないため、ログの閲覧権限と保存期間も制限する。
- エラーログAPIのレート制限は転送ヘッダーではなく接続元を使用する。リバースプロキシ経由では複数利用者が同じ制限を共有することがある。
- `logs/` と `history/` はGit追跡対象外とする。既存ファイルはローカルに保持する。
- 過去のコミット・公開済みログ・ダウンロード済み履歴は削除されない。既存の公開範囲を確認し、必要なら履歴整理や秘密情報の失効を別途行う。

## 検証

`npm test` でゲームロジックとセキュリティ回帰テストを実行する。
精算DBのテストはモックによる検証であり、本番DBへの移行適用確認と実プレイの退室・切断テストは別途必要。
